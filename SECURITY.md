# Security policy

## Supported versions

We provide security updates for the following release lines:

| Version | Supported          |
| ------- | ------------------ |
| 0.1.x   | :white_check_mark: |
| < 0.1   | :x:                |

When in doubt, use the latest published release on [PyPI](https://pypi.org/project/vizqa/).

## Reporting a vulnerability

**Please do not open a public GitHub issue for security vulnerabilities.**

Instead, use one of the following:

1. **GitHub (preferred)**
   Open a **private vulnerability report** for this repository:
   [https://github.com/TinyReasonLabs/vizQA/security/advisories/new](https://github.com/TinyReasonLabs/vizQA/security/advisories/new)

2. **Maintainer contact**
   If private reporting is unavailable or you need an alternate channel, email the
   maintainers.

Include as much detail as you can safely share, for example:

- A short description of the issue and its impact
- Steps to reproduce or a proof of concept
- Affected versions or components
- Whether you believe the issue is already public

We aim to acknowledge reports within a few business days. We will work with you
to understand and validate the report before any public disclosure.

## Scope

This policy applies to the **vizQA** package and this repository. Third-party
services (for example, a self-hosted perception backend or target applications
under test) are outside this project’s control; report issues in those products
to their respective maintainers.

## Disclosure

We ask that you give us a reasonable amount of time to address a confirmed
issue before public disclosure, unless the issue is already actively exploited
or widely known.

Thank you for helping keep vizQA and its users safe.
